# Privacy Boundary

The SeedPEA MCP Adapter does not need personal, confidential, privileged, or
production data to demonstrate its current structural checks. Use synthetic or
minimized declarations during evaluation.

The adapter itself performs no filesystem, network, shell, credential, or
database operation and contains no application logging. It returns field names
and bounded warnings rather than echoing the submitted packet.

For preview and test packets, prefer opaque role or operator identifiers over
personal names. A complete-looking declaration does not establish identity,
employment, appointment, or authority.

This does not control the surrounding MCP host, terminal, transport, process
supervisor, model provider, screen recorder, or institutional logging system.
Operators remain responsible for verifying those separate retention and access
boundaries before supplying any sensitive material.

Public repository issues must not contain secrets, personal records, private
institutional packets, credentials, or vulnerability details that would create
additional risk.
